# Netdebug 使用说明（v0.1.1）

Netdebug 是网络调试助手的 Rust 重写：一个单文件程序，四个页签（调试 / 主站 / 从站 / 网卡），深色界面，不用装、不用联网。

> 状态说明：v0.1.1 里**主站（Modbus TCP）和网卡枚举是真的能用的**；调试页、从站页、网卡改 IP 目前只有界面，点按钮会提示“未接后端”。本文先讲能用的，再讲没接好的，不会把没实现的功能写成已实现。

## 1. 启动

- 有源码：`cargo run`（第一次编译慢一点）；或者 `cargo build --release`，双击 `target\release\netdebug.exe`。
- **重编之前先关掉正在跑的旧程序**，否则 Windows 会锁文件报错（os error 5）。
- 配置保存在 exe 同目录的 `config.json`（上次打开的页签、各页参数、网卡档案都在里面）。配置损坏时自动改名备份成 `config.json.bak`，再恢复一份默认配置，不会闪退。

## 2. 界面总览

| 页签 | 图标 | 干嘛用的 | v0.1.1 状态 |
| --- | --- | --- | --- |
| 调试 | — | 通用收发：TCP/UDP/WebSocket/Modbus 原始数据 | 只有界面，待实现 |
| 主站 | ↻ | 当 Modbus 主站，读/写别的设备 | **Modbus TCP 可用**，RTU 待实现 |
| 从站 | ▣ | 当 Modbus 从站，被别的设备读/写 | 只有界面，待实现 |
| 网卡 | — | 看网卡当前 IP，切 IP 档案 | **枚举和档案保存可用**，改 IP 待实现 |

- 页签可以**拖出来成独立窗口**（多个窗口共享同一份数据），独立窗口里点“⬅ 收回页签”或点右上角 × 就自动收回。
- 日志颜色：蓝色是发送（TX）、绿色是接收/成功（RX/OK）、红色是错误（ERR），琥珀色是提示。

## 3. 主站和从站，到底是什么关系

一句话：**主站是主动问问题的人，从站是被动回答的人。**

|  | 主站（Master） | 从站（Slave） |
| --- | --- | --- |
| 谁先说话 | 主站先发请求 | 从站等着被问 |
| 干什么 | 读从站的数据、写值给从站 | 提供一张数据表，等主站来读/写 |
| 像什么 | 点菜的客人 | 厨房 + 菜单 |
| 例子 | 电脑上的 Netdebug 主站页 | PLC、变频器、传感器网关 |

平时接 PLC 调试，你的电脑就是**主站**，PLC 就是**从站**：主站发“把保持寄存器 0～9 读给我”，从站回“给你 10 个数”。反过来，想在没有 PLC 的时候测主站程序，就需要一个从站来冒充 PLC——这就是从站页以后要干的事。

## 4. 主站怎么用（Modbus TCP，可用）

### 4.1 连一台真实设备（比如 PLC）

1. 切到**主站**页，接入选 **TCP**。
2. 填**远程地址**：PLC 的 IP，比如 `192.168.1.11`；**端口**：Modbus TCP 默认 `502`。
3. **从站地址**：PLC 的站号，一般是 `1`（范围 1～247，要和 PLC 里设的一致）。
4. 选**功能码**（见下表），填**起始地址**和**数量**。
5. 点**启动**（连续轮询，默认每 500 ms 问一次）或**读取一次**（只问一次）。
6. 结果显示在**读取结果**表里，过程记在**请求日志**里。

### 4.2 功能码表

| 功能码 | 名字 | 读/写 | 读到什么 |
| --- | --- | --- | --- |
| 01 | 读线圈 | 读 | 开关量（0/1），如继电器状态 |
| 02 | 读离散输入 | 读 | 开关量（0/1），如按钮、限位 |
| 03 | 读保持寄存器 | 读 | 16 位数，如温度、速度设定值 |
| 04 | 读输入寄存器 | 读 | 16 位数，如实测温度、电流 |
| 05 | 写单线圈 | 写 | 写一个开关（值非 0 = 开，0 = 关） |
| 06 | 写单寄存器 | 写 | 写一个 16 位数 |
| 15 | 写多线圈 | 写 | 一次写多个开关 |
| 16 | 写多寄存器 | 写 | 一次写多个 16 位数 |

- 读线圈/离散输入（01/02）：结果表显示地址和 `● 1` / `○ 0`。
- 读寄存器（03/04）：结果表显示地址、十进制、十六进制三列。
- 数量：读最多 125 个；写多个寄存器时数量 = 你填的值的个数，最多 123 个。

### 4.3 写值怎么填

1. 功能码选 05、06、15 或 16，出现**写入值**框。
2. 填数字，逗号分隔，比如 `100,200`（空格、分号、中文逗号也可以）。
3. 点**写入一次**（写功能码时按钮自动变成“写入一次”）。
4. 日志里出现 `✓ 写入确认` 就是对方收到了；出现 `✗` 看第 4.5 节查原因。
5. 注意：每个值必须是 0～65535；05 写单线圈只取第一个值，非 0 算开。

### 4.4 连续轮询 vs 单次

- **连续轮询**（默认勾上）：点启动后按**轮询间隔**不停地问，适合盯着一个值看变化。间隔默认 500 ms，最小 20 ms，最大 60000 ms。
- **读取一次 / 写入一次**：只发一次就停，适合试一下通不通、改一个值。
- 点**停止**就停下。正在轮询时改了参数要先停止再启动，改动才生效。

### 4.5 报错对照（日志里以 ✗ 开头）

| 报错 | 意思 | 查哪里 |
| --- | --- | --- |
| `✗ 连接 192.168.1.11:502 失败` | 连不上对方 | IP 写错、端口不对、网线/网段不通、对方没开 Modbus TCP 服务、防火墙拦了 |
| `✗ … 失败：…timed out…` | 对方 1 秒没回 | 对方忙、地址不对、线路不稳（超时固定 1 秒） |
| `异常码 1（非法功能码）` | 对方不支持这个功能码 | 换个功能码试（比如有的设备只支持 03/16） |
| `异常码 2（非法数据地址）` | 起始地址 + 数量超出了对方的表 | 把起始地址改小、数量改少，对照设备的地址表 |
| `异常码 3（非法数据值）` | 数量或值不合法 | 数量别超 125，写的值别超 65535 |
| `异常码 4（从站设备故障）` | 对方内部故障 | 看对方设备本身的状态 |
| `✗ 端口非法` / `✗ 远程地址不能为空` | 本地填错了 | 端口填 1～65535 的数字，地址别留空 |
| `未接后端：Modbus RTU 串口待实现` | 选了 RTU | v0.1.1 的 RTU 还没接，改回 TCP |

### 4.6 没有 PLC 时怎么自测（回环测试）

项目自带一个最小假从站 `tools/fake_slave.py`，只会回答 03 读保持寄存器：

1. 装好 Python，命令行跑：`python tools/fake_slave.py 5020`（默认就是 5020）。
2. 主站页填远程地址 `127.0.0.1`，端口 `5020`，功能码 **03**，起始地址 `0`，数量 `10`，点启动。
3. 结果表里出现 10 个寄存器，值每次轮询都会变（100、101……往上走），说明主站收发是通的。
4. 注意：这个假从站**只支持 03**，用 01/02/05/06/15/16 去问它会回异常码 1（非法功能码），这是假从站的限制，不是主站坏了。

## 5. 从站怎么用（v0.1.1：只有界面，还不能用）

**先说清楚：v0.1.1 的从站页点“启动”会弹“未接后端：从站功能待实现”，现在还不能真的当从站用。**下面讲的是这个页面的设计和以后开通后的用法，免得你对着界面猜。

### 5.1 从站是干嘛的

- 程序自己当从站，监听一个端口（TCP 默认 502）或一个串口（RTU），等主站（PLC、Modbus Poll、另一台电脑上的 Netdebug 主站页）来读/写。
- 典型用途：**没有真 PLC 时冒充一个设备**，测主站程序；或者验证一台 PLC 主站的读写逻辑对不对。

### 5.2 界面上有这些（以后开通后这样用）

1. **从站地址**：1～247，主站来问的时候靠这个认你，默认 1。
2. **接入**：Modbus TCP（填监听端口，默认 502）或 Modbus RTU（填串口 COM1、波特率 1200～115200、数据位 7/8、校验 None/Even/Odd、停止位 1/2）。
3. **四区数据表**（各 16 项，现在就能点着玩，但还没人来读它们）：
   - 线圈（01/05/15）：打勾 = 1，不打勾 = 0；
   - 离散输入（02）：同上；
   - 保持寄存器（03/06/16）：填 0～65535 的数；
   - 输入寄存器（04）：同上。
4. **请求日志**：以后主站每次读写都会记一条（功能码、地址、数量、是否成功）。
5. **仿真（自增/随机）**按钮现在是灰的、点不了，等方案定下来再做。

### 5.3 开通后典型的用法（以后）

1. 从站地址设 1，接入 TCP，端口 502，点启动，状态变成“监听中”。
2. 在四区表里填几个值（比如保持寄存器 0 填 100）。
3. 用另一台设备（或本机主站页，地址填 `127.0.0.1`）读它，就能看到你填的值；对方写进来，表里的值会跟着变，日志里有记录。

## 6. 调试页（v0.1.1：只有界面）

调试页是通用收发：TCP Client / TCP Server / UDP / WebSocket / Modbus TCP / Modbus RTU 六种协议，带配置档案、发送历史、原始数据和 Modbus 两种发送方式、四色日志。v0.1.1 里点连接/发送会提示“未接后端”，先别用；等主站稳定后按这个界面接后端。

## 7. 网卡页

### 7.1 能用的

- 自动列出本机网卡（已连接/已断开）和当前 IP（用 PowerShell 枚举，只读）。
- 每个网卡最多 5 条 IP 档案，点格子就能改，**改完自动保存**到 `config.json`（按网卡分开存，换网卡不会串）。
- 默认自带四条示例档案：信捷/雷赛 `192.168.1.11`、欧姆龙 `192.168.1.200`、Festo `192.168.1.2`、施耐德 `192.168.1.201`。第一次用按自己的 PLC 网段改。
- **保存配置**按钮：把当前档案写进 `config.json`。

### 7.2 还不能用的

- **应用此 IP**（点确认后提示“未接后端：netsh 调用待实现”）、**恢复 DHCP**、**重命名适配器**：都要调 netsh 且要管理员权限，等打包时加提权清单后再接。

## 8. 常见问题

- **主站一直连不上**：先拿第 4.6 节的假从站自测，通了就是对方设备或网络的问题；不通就看报错表。最常见的是 IP/端口写错，或者电脑和 PLC 不在同一网段。
- **读到了但值不对**：确认起始地址是不是从 0 开始数（有的设备地址表从 1 开始写，实际要填 0）；寄存器是 16 位，超过 65535 的值要占两个寄存器。
- **从站/调试页点按钮没反应**：不是卡死，是 v0.1.1 还没接后端，提示条里会写“未接后端”。
- **程序一打开有个黑窗口**：v0.1.1 已修掉，双击 exe 只有应用窗口；如果还有，确认跑的是新版（顶栏显示 v0.1.1）。
- **标题栏一开始是白的**：v0.1.1 已修，主窗口和弹出窗口从第一帧就是深色；如果还有，确认跑的是新版。
- **界面太大/太小**：程序首帧会自动缩到屏幕内，之后可以自己拖；250% 缩放的屏幕上验证过。
