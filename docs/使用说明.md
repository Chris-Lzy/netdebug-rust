# Netdebug 使用说明（v0.2.0）

Netdebug 是网络调试助手的 Rust 重写：一个单文件程序，四个页签（调试 / 主站 / 从站 / 网卡），深色界面，不用装、不用联网。

> 状态说明：v0.2.0 里四个页签的功能都接通了（调试六种协议、主站 TCP/RTU、从站模拟、网卡改 IP）。唯一还灰着的按钮是**从站页的“仿真（自增/随机）”**——那是方案没定、有意留到以后做的，不是漏了。Windows 真机上的实测（真实串口、真实 PLC、netsh 改 IP）还没有，Linux 虚拟机上能验的都验过了，见第 9 节。

## 1. 启动

- 有源码：`cargo run`（第一次编译慢一点）；或者 `cargo build --release`，双击 `target\release\netdebug.exe`。
- **重编之前先关掉正在跑的旧程序**，否则 Windows 会锁文件报错（os error 5）。
- 配置保存在 exe 同目录的 `config.json`（上次打开的页签、各页参数、网卡档案都在里面）。配置损坏时自动改名备份成 `config.json.bak`，再恢复一份默认配置，不会闪退。

## 2. 界面总览

| 页签 | 图标 | 干嘛用的 | v0.2.0 状态 |
| --- | --- | --- | --- |
| 调试 | — | 通用收发：TCP/UDP/WebSocket/Modbus 原始数据 | ✅ 六种协议都可用 |
| 主站 | ↻ | 当 Modbus 主站，读/写别的设备 | ✅ Modbus TCP / RTU 都可用 |
| 从站 | ▣ | 当 Modbus 从站，被别的设备读/写 | ✅ TCP / RTU 监听都可用 |
| 网卡 | — | 看网卡当前 IP，切 IP 档案 | ✅ 枚举、档案保存、改 IP / DHCP / 重命名都可用 |

- 页签可以**拖出来成独立窗口**（多个窗口共享同一份数据），独立窗口里点“⬅ 收回页签”或点右上角 × 就自动收回。
- 日志颜色：蓝色是发送（TX）、绿色是接收/成功（RX/OK）、红色是错误（ERR），琥珀色是提示。

## 3. 主站和从站，到底是什么关系

一句话：**主站是主动问问题的人，从站是被动回答的人。**

|  | 主站（Master） | 从站（Slave） |
| --- | --- | --- |
| 谁先说话 | 主站先发请求 | 从站等着被问 |
| 干什么 | 读从站的数据、写值给从站 | 提供一张数据表，等主站来读/写 |
| 像什么 | 点菜的客人 | 厨房 + 菜单 |
| 例子 | 电脑上的 Netdebug 主站页 | PLC、变频器、传感器网关 |

平时接 PLC 调试，你的电脑就是**主站**，PLC 就是**从站**：主站发“把保持寄存器 0～9 读给我”，从站回“给你 10 个数”。反过来，想在没有 PLC 的时候测主站程序，就需要一个从站来冒充 PLC——这就是从站页以后要干的事。

## 4. 主站怎么用（Modbus TCP，可用）

### 4.1 连一台真实设备（比如 PLC）

1. 切到**主站**页，接入选 **TCP** 或 **RTU**。
2. TCP：填**远程地址**（PLC 的 IP，比如 `192.168.1.11`）和**端口**（Modbus TCP 默认 `502`）；RTU：填**串口**（如 `COM1`）和**波特率**（1200～115200，固定 8 数据位 / 无校验 / 1 停止位）。
3. **从站地址**：PLC 的站号，一般是 `1`（范围 1～247，要和 PLC 里设的一致）。
4. 选**功能码**（见下表），填**起始地址**和**数量**。
5. 点**启动**（连续轮询，默认每 500 ms 问一次）或**读取一次**（只问一次）。
6. 结果显示在**读取结果**表里，过程记在**请求日志**里。

RTU 说明：帧尾用 3.5 个字符的静默间隔判断（波特率高于 19200 时按公式算，低于等于 19200 时固定 1.75 ms），CRC16 校验不对的帧直接丢弃并记一条日志；响应超时固定 1 秒，和 TCP 一样。

### 4.2 功能码表

| 功能码 | 名字 | 读/写 | 读到什么 |
| --- | --- | --- | --- |
| 01 | 读线圈 | 读 | 开关量（0/1），如继电器状态 |
| 02 | 读离散输入 | 读 | 开关量（0/1），如按钮、限位 |
| 03 | 读保持寄存器 | 读 | 16 位数，如温度、速度设定值 |
| 04 | 读输入寄存器 | 读 | 16 位数，如实测温度、电流 |
| 05 | 写单线圈 | 写 | 写一个开关（值非 0 = 开，0 = 关） |
| 06 | 写单寄存器 | 写 | 写一个 16 位数 |
| 15 | 写多线圈 | 写 | 一次写多个开关 |
| 16 | 写多寄存器 | 写 | 一次写多个 16 位数 |

- 读线圈/离散输入（01/02）：结果表显示地址和 `● 1` / `○ 0`。
- 读寄存器（03/04）：结果表显示地址、十进制、十六进制三列。
- 数量：读线圈/离散输入最多 2000 个，读寄存器最多 125 个；写多个线圈最多 1968 个，写多个寄存器最多 123 个。界面上填大了会自动夹到上限。

### 4.3 写值怎么填

1. 功能码选 05、06、15 或 16，出现**写入值**框。
2. 填数字，逗号分隔，比如 `100,200`（空格、分号、中文逗号也可以）。
3. 点**写入一次**（写功能码时按钮自动变成“写入一次”）。
4. 日志里出现 `✓ 写入确认` 就是对方收到了；出现 `✗` 看第 4.5 节查原因。
5. 注意：每个值必须是 0～65535；05 写单线圈只取第一个值，非 0 算开。

### 4.4 连续轮询 vs 单次

- **连续轮询**（默认勾上）：点启动后按**轮询间隔**不停地问，适合盯着一个值看变化。间隔默认 500 ms，最小 20 ms，最大 60000 ms。
- **读取一次 / 写入一次**：只发一次就停，适合试一下通不通、改一个值。
- 点**停止**就停下。正在轮询时改了参数要先停止再启动，改动才生效。

### 4.5 报错对照（日志里以 ✗ 开头）

| 报错 | 意思 | 查哪里 |
| --- | --- | --- |
| `✗ 连接 192.168.1.11:502 失败` | 连不上对方 | IP 写错、端口不对、网线/网段不通、对方没开 Modbus TCP 服务、防火墙拦了 |
| `✗ … 失败：…timed out…` | 对方 1 秒没回 | 对方忙、地址不对、线路不稳（超时固定 1 秒） |
| `异常码 1（非法功能码）` | 对方不支持这个功能码 | 换个功能码试（比如有的设备只支持 03/16） |
| `异常码 2（非法数据地址）` | 起始地址 + 数量超出了对方的表 | 把起始地址改小、数量改少，对照设备的地址表 |
| `异常码 3（非法数据值）` | 数量或值不合法 | 数量别超 125，写的值别超 65535 |
| `异常码 4（从站设备故障）` | 对方内部故障 | 看对方设备本身的状态 |
| `✗ 端口非法` / `✗ 远程地址不能为空` | 本地填错了 | 端口填 1～65535 的数字，地址别留空 |
| `✗ 打开串口 COM1 失败` | 串口不存在或被别的程序占了 | 换个串口号，或关掉占用它的程序（主站和从站 RTU 不能同时占同一个串口） |
| `✗ … CRC 校验失败` | 线路干扰或对方帧不完整 | 检查接线、波特率和站地址；偶尔出现一次一般是干扰 |

### 4.6 没有 PLC 时怎么自测（回环测试）

项目自带一个最小假从站 `tools/fake_slave.py`，只会回答 03 读保持寄存器：

1. 装好 Python，命令行跑：`python tools/fake_slave.py 5020`（默认就是 5020）。
2. 主站页填远程地址 `127.0.0.1`，端口 `5020`，功能码 **03**，起始地址 `0`，数量 `10`，点启动。
3. 结果表里出现 10 个寄存器，值每次轮询都会变（100、101……往上走），说明主站收发是通的。
4. 注意：这个假从站**只支持 03**，用 01/02/05/06/15/16 去问它会回异常码 1（非法功能码），这是假从站的限制，不是主站坏了。

## 5. 从站怎么用（可用）

### 5.1 从站是干嘛的

- 程序自己当从站，监听一个端口（TCP 默认 502）或一个串口（RTU），等主站（PLC、Modbus Poll、另一台电脑上的 Netdebug 主站页）来读/写。
- 典型用途：**没有真 PLC 时冒充一个设备**，测主站程序；或者验证一台 PLC 主站的读写逻辑对不对。

### 5.2 界面上有这些

1. **从站地址**：1～247，主站来问的时候靠这个认你，默认 1。
2. **接入**：Modbus TCP（填监听端口，默认 502）或 Modbus RTU（填串口 COM1、波特率 1200～115200、数据位 7/8、校验 None/Even/Odd、停止位 1/2）。
3. **四区数据表**（各 16 项）：
   - 线圈（01/05/15）：打勾 = 1，不打勾 = 0；
   - 离散输入（02）：同上；
   - 保持寄存器（03/06/16）：填 0～65535 的数；
   - 输入寄存器（04）：同上。
4. **请求日志**：主站每次读写都记一条（功能码、地址、数量、是否成功），最多留 200 条。
5. **仿真（自增/随机）**按钮现在是灰的、点不了，等方案定下来再做。

### 5.3 典型的用法

1. 从站地址设 1，接入 TCP，端口 502，点启动，状态变成“监听中 :502”。
2. 在四区表里填几个值（比如保持寄存器 0 填 100）。
3. 用另一台设备（或本机主站页，地址填 `127.0.0.1`）读它，就能看到你填的值；对方写进来，表里的值会跟着变，日志里有记录。

注意：

- TCP 从站监听的是 `0.0.0.0`，**局域网里的设备都能连进来**（和调试页的 TCP Server 只绑本机不一样，从站就是要给别人连的）。
- 表里改值**立即生效**，运行中改也行；对方写进来的值界面上马上能看到。
- 四区表和从站地址、端口、波特率都会存进 `config.json`，下次打开还原。
- 主站和从站可以**同时跑**（比如本机主站页读本机从站页，做回环测试），只要别让两个 RTU 同时占同一个串口。
- 站地址不对的请求会被忽略（日志里记一条），不回响应；地址越界或功能码不支持回异常码 2 / 1。

## 6. 调试页（可用）

调试页是通用收发：TCP Client / TCP Server / UDP / WebSocket / Modbus TCP / Modbus RTU 六种协议。

### 6.1 连接

- 选协议、填好地址，点**连接**；再点一次就是断开。连接状态显示在按钮下面。
- **TCP Client**：5 秒连接超时；勾上**断线自动重连**后，断线或连不上会自动重试，间隔 1 秒 → 2 秒 → 5 秒，之后一直 5 秒，直到你点断开。
- **TCP Server**：只绑 `127.0.0.1`（仅本机），多客户端都能连，每个客户端的收发都带地址记在日志里；发送是发给**所有**已连接的客户端。
- **UDP**：监听 `0.0.0.0`（设备要能发进来）。**回包发给最近一次收到数据的发送方**（原来老版本有个 bug，回包发错了目标，这里修好了）；还没收过数据时，发给界面上填的远程地址。
- **WebSocket**：只支持 `ws://`，不支持 `wss://`（没开 TLS）。断线自动重连和 TCP Client 一样。
- **Modbus TCP / RTU**：点连接就是开始轮询（和主站页一样，功能码、地址、数量、间隔都在下面的 Modbus 页签里填）；点断开就停轮询。RTU 的串口参数在连接面板里填。

### 6.2 发送

- **原始数据**页签：输入框里填内容，点**发送**或按 `Ctrl+Enter`。勾上 **HEX** 时按十六进制发（比如 `01 03 00 00 00 0A`，空格可有可无）；不勾按文本发。**结尾符**可以加 `\n` 或 `\r\n`。**定时发送**勾上后按填的间隔反复发当前内容。
- 发过的内容会进**发送历史**（输入框左边的小下拉箭头），点一条就填回去，不用重打。
- **Modbus** 页签：从站地址、功能码、地址、数量和主站页一样；**执行**是发一次，**轮询**勾上是按间隔一直发。功能码是写（05/06/15/16）时会出现**值**框，填法和主站页一样（`1,0,1` / `100,200` / `0x0064` / `on|off`）。
- 读回来的值直接记在日志里（`← 地址=0 寄存器：100, 200` 这样）。

### 6.3 配置档案和日志

- **配置档案**：下拉选一个档案就把它的协议和地址填进界面；改好参数后在**档案名**框里填名字，点**保存档案**就存下来（同名覆盖，没有就新增），存在 `config.json` 里。
- 日志工具条：**HEX**（收发按十六进制显示）、**时间戳**、**自动滚动**、**帧数**、**清空**、**保存**。保存是把日志写成 `netdebug-日期-时间.log`，放在 `config.json` 同目录（exe 旁边）。

## 7. 网卡页

### 7.1 能用的

- 自动列出本机网卡（已连接/已断开）和当前 IP（用 PowerShell 枚举，只读）。
- 每个网卡最多 5 条 IP 档案，点格子就能改，**改完自动保存**到 `config.json`（按网卡分开存，换网卡不会串）。
- 默认自带四条示例档案：信捷/雷赛 `192.168.1.11`、欧姆龙 `192.168.1.200`、Festo `192.168.1.2`、施耐德 `192.168.1.201`。第一次用按自己的 PLC 网段改。
- **保存配置**按钮：把当前档案写进 `config.json`。

### 7.2 改 IP 怎么用

- **应用此 IP**：在档案表里点一行后面的**应用此 IP**，弹窗里确认一遍（上面写着要设的 IP/掩码/网关/DNS），点确定。改 IP 是后台跑 netsh，界面不会卡；状态栏先显示“正在应用 IP…”，成功后显示 `✓ 已应用 192.168.1.11`，当前 IP 会自动刷新。网关留空就不设网关；掩码留空默认 `255.255.255.0`；DNS 留空就不改 DNS（只填了首选就只设首选）。
- **恢复 DHCP**：点一下就把地址和 DNS 都改回自动获取，同样后台跑，成功后当前 IP 自动刷新。
- **重命名适配器**：点**重命名适配器**，填新名字，点确定。成功后选中项和这块网卡的档案表一起改成新名字，不会丢档案。
- **管理员权限**：改 IP、恢复 DHCP、重命名都要调 netsh，必须管理员权限。发布版 exe 里嵌了 `requireAdministrator` 清单，**启动时就会弹一次 UAC**，点了“是”再进去就是管理员身份。如果没提权就点改 IP，状态栏会明确告诉你“需要管理员权限”。
- 注意：改 IP 每条 netsh 命令最多等 10 秒，超时会停在当步并报原因；IP、掩码、网关、DNS 填错格式会在调 netsh 之前就拦下来，不会乱发命令。

## 8. 常见问题

- **主站一直连不上**：先拿第 4.6 节的假从站自测，通了就是对方设备或网络的问题；不通就看报错表。最常见的是 IP/端口写错，或者电脑和 PLC 不在同一网段。
- **读到了但值不对**：确认起始地址是不是从 0 开始数（有的设备地址表从 1 开始写，实际要填 0）；寄存器是 16 位，超过 65535 的值要占两个寄存器。
- **程序一打开有个黑窗口**：v0.1.1 已修掉，双击 exe 只有应用窗口；如果还有，确认跑的是新版（顶栏显示 v0.2.0）。
- **标题栏一开始是白的**：v0.1.1 已修，主窗口和弹出窗口从第一帧就是深色；如果还有，确认跑的是新版。
- **改 IP 提示“需要管理员权限”**：启动时没点 UAC 的“是”，或者 exe 的提权清单没嵌进去（改了清单要整包重编）。用管理员身份重新运行一次。
- **界面太大/太小**：程序首帧会自动缩到屏幕内，之后可以自己拖；250% 缩放的屏幕上验证过。
